## SECTION 1: RESEARCH PHASE VALIDATION

### Avatar Research

- [ ] Demographics definidas (idade, gênero, renda, localização)
- [ ] Psychographics definidas (valores, crenças, estilo de vida)
- [ ] Situação atual documentada
- [ ] Tentativas anteriores listadas com por que falharam
- [ ] Linguagem específica do prospect coletada
- [ ] "O que nunca admitiriam" identificado

### Pain Point Mining

- [ ] Dor superficial identificada
- [ ] Dor social mapeada (como afeta relacionamentos)
- [ ] Dor emocional documentada (como se sentem)
- [ ] Dor de identidade explorada (o que diz sobre quem são)
- [ ] Dor existencial/medo profundo identificado
- [ ] Custo da dor quantificado (tempo, dinheiro, oportunidades)
- [ ] Momento mais agudo da dor identificado

### Desire Mapping

- [ ] Desejo declarado documentado
- [ ] Desejo secreto identificado (status, validação, vingança)
- [ ] Visão de sucesso descrita visualmente
- [ ] Sensação de sucesso descrita emocionalmente
- [ ] "Primeira coisa que fariam" identificada

### Proof Arsenal

- [ ] Testemunhos com resultados específicos coletados
- [ ] Estudos/pesquisas com fontes documentados
- [ ] Credenciais do criador listadas
- [ ] Cobertura de mídia compilada
- [ ] Números impressionantes identificados

### Competitive Analysis

- [ ] 3+ concorrentes analisados
- [ ] Promessas dos concorrentes documentadas
- [ ] Mecanismos dos concorrentes identificados
- [ ] Gaps/oportunidades identificados
- [ ] Diferenciação definida

### Key Belief

- [ ] A ÚNICA coisa que precisam acreditar está claramente articulada

**Target:** 4.0+

## SECTION 2: MECHANISM PHASE VALIDATION

### Mechanism Definition

- [ ] Tipo de mecanismo identificado:
  - [ ] Científico/Biológico
  - [ ] Descoberta/Breakthrough
  - [ ] Sistema/Método
  - [ ] Ingrediente/Componente
  - [ ] História de Origem
  - [ ] Contrário/Reversal

- [ ] Mecanismo explica COMO (não apenas O QUE)
- [ ] Mecanismo é diferente do que concorrentes usam
- [ ] Mecanismo conecta logicamente à promessa
- [ ] Mecanismo pode ser explicado em 1 frase

### Mechanism Strength Test

| Pergunta | SIM/NÃO |
|----------|---------|
| É ÚNICO? (Não ouviram antes) | |
| É ACREDITÁVEL? (Faz sentido lógico) | |
| É SIMPLES? (Explica em 1 frase) | |
| É ESPECÍFICO? (Tem nome/número/detalhe) | |
| É PROPRIETÁRIO? (Só você pode usar) | |

**Scoring:**
- 5 SIMs = ✅ Mecanismo forte
- 3-4 SIMs = 🔄 Fortalecer
- 0-2 SIMs = ❌ Recriar

### Mechanism Naming

- [ ] Nome proprietário criado
- [ ] Nome tem 3-4 palavras (ideal)
- [ ] Nome inclui número ou especificidade (se possível)
- [ ] Nome usa palavras sensoriais/ativas
- [ ] Nome é memorável

### Mechanism One-Liner

- [ ] One-liner completo escrito
- [ ] Inclui: O QUE é + COMO funciona + POR QUE é diferente
- [ ] Pode ser usado em headlines e bullets

### Mechanism Proof

- [ ] Pelo menos 1 estudo/pesquisa suporta o mecanismo
- [ ] Pelo menos 1 expert/autoridade valida
- [ ] Pelo menos 1 testemunho demonstra o mecanismo em ação

## SECTION 3: BRIEF PHASE VALIDATION

### Section 1: Headline

- [ ] Headline principal combina benefício + mecanismo + curiosidade
- [ ] Sub-headline expande promessa e adiciona credibilidade
- [ ] 2-3 headlines de backup para teste
- [ ] Nenhuma headline usa linguagem hype sem suporte

### Section 2: Lead

- [ ] Tipo de lead definido (story/problem/news/question/prediction)
- [ ] Primeiras 3-5 frases prendem atenção
- [ ] Lead estabelece rapport/identificação
- [ ] Transição para mecanismo é natural

### Section 3: Mechanism Reveal

- [ ] Mecanismo é nomeado e explicado
- [ ] Ciência/lógica por trás está simplificada
- [ ] Diferenciação está clara
- [ ] Prova do mecanismo está presente
- [ ] Objeções "bom demais para ser verdade" endereçadas

### Section 4: Body/Benefits

- [ ] 5+ benefícios principais listados
- [ ] Benefícios em ordem de importância
- [ ] Cada benefício conectado ao mecanismo
- [ ] Cada benefício tem prova associada
- [ ] Future pacing presente para principais benefícios
- [ ] Principais objeções endereçadas ao longo do body

### Section 5: Credibility

- [ ] História do criador incluída
- [ ] Qualificações/credenciais listadas
- [ ] 3-5 testemunhos principais com resultados específicos
- [ ] Prova de autoridade (mídia, experts)
- [ ] Números impressionantes apresentados

### Section 6: Offer

- [ ] Componentes do produto principal listados com valores
- [ ] 3+ bônus incluídos com valores
- [ ] Value stack completo (total vs investimento)
- [ ] Ancoragem de preço presente
- [ ] Garantia definida com:
  - [ ] Nome da garantia
  - [ ] Duração
  - [ ] Termos
  - [ ] Processo

### Section 7: Close

- [ ] Urgência com razão legítima
- [ ] Risk reversal reforçado
- [ ] Recap final de benefícios
- [ ] CTA claro e específico
- [ ] Pelo menos 1 P.S. estratégico

## SECTION 4: COPY PHASE VALIDATION

### Draft Quality

- [ ] Segue a estrutura do brief
- [ ] Todas as seções estão presentes
- [ ] Nenhuma seção pulada ou incompleta

### Enhancement Check

- [ ] Headlines são compelling
- [ ] Prova suficiente em cada seção
- [ ] Linguagem emocional presente
- [ ] Transições entre seções suaves
- [ ] Fluxo lógico do início ao fim

### Editing Check

- [ ] Palavras desnecessárias cortadas
- [ ] Frases complexas simplificadas
- [ ] Repetições eliminadas
- [ ] Todos os claims têm prova
- [ ] Voz consistente do início ao fim

### Polish Check

- [ ] Lido em voz alta - sem tropeços
- [ ] Formatação consistente (headers, bullets, espaçamento)
- [ ] CTA impossível de perder
- [ ] Erros ortográficos corrigidos
- [ ] Links/botões testados (se aplicável)

### Copy Techniques Applied

- [ ] Tom conversacional (não corporativo)
- [ ] Especificidade (números, nomes, detalhes)
- [ ] Proof stacking (claim → proof → implication)
- [ ] Future pacing (visualização de sucesso)
- [ ] Objection handling (endereça dúvidas proativamente)

## SECTION 5: FINAL VALIDATION

### The Stefan Georgi Questions

- [ ] A research respondeu "O que precisam ACREDITAR"?
- [ ] O mecanismo responde "Por que ISSO é diferente"?
- [ ] O brief é o esqueleto COMPLETO da copy?
- [ ] A copy apenas EXECUTA o que o brief definiu?

### Hit Rate Predictors

| Fator | Presente? |
|-------|-----------|
| Mecanismo único e forte | |
| Avatar super específico | |
| Dor agitada adequadamente | |
| Benefícios com prova | |
| Credibilidade estabelecida | |
| Oferta irresistível | |
| Urgência legítima | |
| Garantia remove risco | |

**8/8 = Alta probabilidade de conversão**
**6-7/8 = Boa probabilidade**
**5 ou menos = Revise antes de lançar**

### Pre-Launch Checklist

- [ ] Research document arquivado para reuso
- [ ] Mechanism statement salvo
- [ ] Brief completo salvo
- [ ] Copy final revisada por segunda pessoa (se possível)
- [ ] Versão de teste A/B preparada (se aplicável)

## QUICK REFERENCE

### RMBC Quality Thresholds

| Fase | Minimum | Good | Excellent |
|------|---------|------|-----------|
| Research Score | 3.0 | 4.0 | 4.5+ |
| Mechanism SIMs | 3/5 | 4/5 | 5/5 |
| Brief Score | 10/14 | 12/14 | 14/14 |
| Hit Predictors | 5/8 | 7/8 | 8/8 |

### Red Flags (Stop e Revise)

- ❌ Mechanism score 2/5 ou menos
- ❌ Avatar genérico sem linguagem específica
- ❌ Benefits sem prova
- ❌ Urgência fake/não justificada
- ❌ CTA vago ou difícil de encontrar
- ❌ Copy que "pulou" seções do brief

### Signs of Excellence

- ✅ Mechanism é memorável e único
- ✅ Pode ouvir a voz do prospect na copy
- ✅ Cada claim tem prova adjacente
- ✅ Transições são seamless
- ✅ Ler em voz alta é prazeroso
